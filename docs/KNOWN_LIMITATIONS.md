## Known limitations

### Content / placeholders

1. **No GitHub links exist for any project.** All 4 projects in `src/content/projects.ts` have `links.github = { url: null, isPrivate: true }`. `ProjectLinksRow.tsx` renders a disabled "Private codebase" tile for every one of them.
2. **No demo links exist for any project.** No project object in `projects.ts` even defines a `links.demo` key.
3. **No public GitHub profile link.** `src/content/social.ts`'s `github` entry has `url: null` — renders as "Coming soon" on `/contact` and is omitted from the footer/`PersonJsonLd`'s `sameAs`.
4. **No LinkedIn link.** Same pattern — `linkedin: { url: null }`.
5. **No resume file.** `social.ts`'s `resume: { url: null }` — the Header (desktop + mobile) and Footer both render a disabled "Resume" state; `public/resume/` exists as a directory but is empty.
6. **No About-page photo.** `about.ts`'s `photoSrc: null` — `/about` renders a bordered placeholder box with the label "Photo" instead of an image.
7. **No project has a confirmed `outcome`.** The `Project.outcome` field is `undefined` for all 4 projects — the "Outcome" section on `/projects/[slug]` never renders.

None of the above are bugs — they are the codebase's explicit, deliberate placeholder convention (`null` = "not supplied yet," documented in `content/types.ts`'s header comment). They are listed here because they are real, current gaps in the live site's content, not because the code handling them is wrong.

### Testing / tooling

8. **Playwright / end-to-end testing: NOT CONFIGURED.** No `playwright.config.ts`, no e2e test directory. Only Vitest unit/schema tests exist (`src/content/content.test.ts`, `src/components/layout/Header.test.tsx` — 16 tests total).
9. **Lighthouse / performance auditing: NOT CONFIGURED.** No Lighthouse CI config, no performance budget, no CI step for it.
10. **`NEXT_PUBLIC_SITE_URL` is unset by default**, falling back to `http://localhost:3000` (`src/lib/site-url.ts`). This must be set in the production environment before deploy, or `metadataBase`, Open Graph tags, `sitemap.xml`, `robots.txt`, and `PersonJsonLd`'s `url` will all point at localhost.

### Design / product decisions worth knowing

11. **Single dark theme only — no light mode.** Explicit, deliberate decision (see `globals.css` header comment). A future request for light mode would require defining a full parallel token set, not just flipping a class.
12. **No prev/next navigation between projects** on `/projects/[slug]` — only a "← All projects" link back to the index.
13. **`/dev/design-system` is reachable by direct URL** (not gated by auth) — it's excluded from the nav and from search indexing (`noindex`, disallowed in `robots.ts`), but is not otherwise protected.

### Interaction gaps

14. **`TechMap`'s hover-driven tech↔project highlight has no explicit touch/tap fallback.** It reacts to `onMouseEnter`/`onFocus`/`onMouseLeave`/`onBlur` only — no `onClick` toggle. Keyboard-focus (Tab) still triggers the highlight correctly; a touch-only user tapping a badge gets only the underlying link/button's own tap behavior, not a guaranteed highlight state.
15. **No explicit body-scroll lock while the Trailer overlay is open.** No `document.body.style.overflow` (or equivalent) toggle exists in `TrailerGate.tsx`/`Trailer.tsx`. The overlay is opaque and full-viewport, so this has no visible effect in normal use, but background scroll position could still change during the trailer (e.g. via a focused element or keyboard scroll) since nothing is technically preventing it.

### Static export / GitHub Pages

16. **Verified-harmless RSC segment-prefetch 404s.** When the static export (`out/`) is served by any plain static file server — verified with `npx serve`, which behaves like GitHub Pages here (no server-side rewrites) — the browser Network tab shows 404s for requests like `/projects/__next.projects.__PAGE__.txt`. This is a per-route-segment React Server Components prefetch payload that this Next.js version's static export writes to disk under a nested path (`__next.projects/__PAGE__.txt`) different from the flat, dot-joined path its own client router requests. Reproduces identically with `trailingSlash` on or off, confirming it isn't caused by this repo's configuration.
    - **Confirmed non-blocking.** Next.js's router explicitly catches the failure — the console logs `"Failed to fetch RSC payload for <url>. Falling back to browser navigation."` — and falls back to fetching the full route's `index.txt`/`<route>.txt` RSC payload, which always succeeds. Verified by clicking through every nav link, every project detail page, and confirming complete, correct content renders every time.
    - **Cost:** a console error (visible to developers via devtools, not to typical visitors) and a marginally slower transition for the affected navigations. No fix is available from this repo's configuration — it's internal to this Next.js version's static-export/client-router interaction.
17. **`next/font/google` and `next/image` are unaffected by the export config change** — fonts are self-hosted at build time regardless of `output` mode; `next/image` requires `images.unoptimized: true` under static export (now set), which disables on-the-fly resizing/format conversion but does not change what renders (there is currently no real photo in use, so this has zero visible effect today).

**Resolved during the repository cleanup pass** (kept here as a record, not as outstanding debt): the unused `src/content/index.ts` content barrel was deleted (nothing imported it); the never-called `getTechnologiesForProject()` export was removed from `src/content/technologies.ts`; the unused `fadeIn`/`scaleIn` Framer Motion variants were removed from `src/lib/motion/variants.ts`; the stale `"see content/README.md"` comment (pointing at a file that never existed) was removed from `src/content/types.ts`; `.claude/` and `CLAUDE.md` (Claude Code-specific local tooling, never required by the app) were deleted and added to `.gitignore`.

**Resolved during the static-export/GitHub Pages preparation pass** (real bugs, not config additions):

- **`npm run dev` returned `500` on every route.** Root cause: Tailwind v4's automatic content scanner reads prose inside `.md` files, not just source code; this repo's own documentation quotes real utility classes and describes token groups with a wildcard shorthand (`--duration-*`), which the scanner misread as a malformed arbitrary-value utility candidate, producing invalid generated CSS. `next build` only ever showed this as a tolerated warning; `next dev` treated the identical parse failure as fatal. Fixed with `@source not "../../*.md"` / `@source not "../../docs/**/*"` in `src/app/globals.css`. Confirmed via a controlled before/after test (removed docs → error gone; restored docs with the fix → error stays gone, in both `build` and `dev`).
- **`npm run typecheck` failed on a genuinely clean checkout.** `tsc --noEmit` alone depends on ambient types (`LayoutProps`, `PageProps`) that only `next dev`/`next build` previously generated; a truly fresh checkout (no residual `.next/`) failed with `Cannot find name 'LayoutProps'`. This almost certainly affected `.github/workflows/ci.yml` on every real CI run (fresh checkout every time), not just local development, though it was never actually observed failing in CI before this fix. Fixed by changing the `typecheck` script to `next typegen && tsc --noEmit`.

**Resolved during the trailer redesign** (real bugs found while building the original 6-scene sequence):

- **Every trailer scene's content was invisible.** `AnimatePresence mode="wait"` combined with a single dynamically-keyed `motion.div` never reached its `animate` target in this exact setup — verified via computed styles (`opacity`/`transform` frozen at the scene's `initial` value for its entire duration) and `onAnimationComplete` never firing, across every scene, confirmed after a full dev-server restart (ruling out an HMR artifact). Fixed by removing `mode="wait"` (plain `AnimatePresence`), which also lets consecutive scenes cross-fade rather than hard-cutting. The same bug and fix applied inside the (since-removed) `ArchitectureMorph.tsx`'s two internal crossfades.
- **The (since-removed) `Convergence.tsx`'s converging nodes threw `<circle> attribute cx/cy: Expected length, "undefined"` in the console.** The animated circles set `cx`/`cy` only in `animate` (as a 2-value array), with no `initial` value for Framer Motion to interpolate from. Fixed by setting `initial={{ cx: p.x, cy: p.y, ... }}` explicitly, matching the pre-existing working pattern already used by `SystemBoot.tsx`'s own traveling dot.
- **The Trailer's chapter labels are no longer a hand-synced parallel array.** The old `CHAPTER_LABELS` constant in `Trailer.tsx` (technical debt item, since removed) is gone — `TrailerScene` now has an `hudLabel` field populated per-scene in `content/trailer.ts` and read directly by `TrailerHud.tsx`.

**Resolved during the trailer scope-down and opening-scene redesign** (the trailer was narrowed from 6 scenes to exactly 4 — Origin/Building/Real World/Identity — removing every project-named beat, and the opening and career-timeline scenes were redesigned):

- **`systems` and `converge` scenes removed entirely**, along with their visuals (`ArchitectureMorph.tsx`, `Convergence.tsx`, both deleted) and their `TrailerSceneId` values — the `systems` scene named real projects (Vrozart Finance, HAUT, Van Sales & Distribution ERP, Viblets) and their architectures, which no longer belongs in a trailer scoped to the four career-arc beats. Total duration dropped from ~28s to ~19s (4000+5000+5000+5000ms) accordingly.
- **`SystemBoot`'s ring diagram replaced with a linear Input → Process → System diagram** (thin connecting lines, not a circle) — a violet signal travels node to node and triggers the headline's word-by-word reveal on arrival, reusing the same "signal travels, points illuminate on arrival" language `CareerTimeline` already used.
- **`CareerTimeline`'s year row (`2020`/`2023`/`2025`) rendered with zero visible gap between years, reading as one fused number (e.g. "20202023"), regardless of font size.** Root cause: the scene wrapper `Trailer.tsx` renders every scene's content into (`className="flex flex-col items-center"`) has no width of its own — it's a shrink-to-fit flex item. `CareerTimeline`'s outer `w-full` therefore resolved against that shrink-wrapped ancestor instead of the viewport, so the container always ended up exactly as wide as its own content, leaving `justify-between` with zero leftover space to turn into gaps — confirmed via `getBoundingClientRect()`, where the container's width and the sum of its children's widths matched to the sub-pixel. Fixed by giving the scene's `<CareerTimeline>` call site a viewport-relative width (`w-[min(calc(100vw-3rem),48rem)]`) instead of `w-full`, which resolves against the viewport directly and doesn't depend on the ancestor's sizing.
- **`TrailerStage` gained a `minimal` prop** (set only for `boot` and `timeline`) that dims the backdrop's grid/arcs further and drops the outermost ring, so those two scenes' own small diagrams aren't competing with large background rings — `stack` and `identity` are unaffected.
